User journey

Domain first, then computation

01 · CONTEXT

Choose a domain

Fraud, bioinformatics, cybersecurity, social networks, e-commerce, knowledge graphs, infrastructure, mobility, or general analysis.

02 · INPUT

Upload research files

Canonical graph JSON and edge lists are normalized. Query graphs, motifs, updates, and partitions receive explicit roles.

03 · PLAN

Resolve formal intent

The planner selects one of the 20 exact problem definitions and only continues when a validated operation exists.

04 · VALIDATE

Constrain execution

The orchestrator checks every backend, parameter, output flag, file ID, ownership boundary, and compiled capability.

05 · RUN

Execute on the GPU

A single durable worker owns the compute GPU. Queued, running, interpreting, and terminal states stream live to the browser.

06 · EXPLORE

Interpret and visualize

The analyst grounds findings in result paths and chooses safe tables, metrics, charts, timelines, or interactive network views.

Two LLM modes

One model, two narrow responsibilities

ModeReceivesProducesCannot do
PlannerUser question, selected domain, graph metadata, retrieved catalog recordsA schema-constrained route and ExecutionPlanExecute commands, invent parameters, or substitute an unsupported problem
AnalystFormal problem, validated plan, bounded result summary, domain contextGrounded findings, limitations, follow-ups, and visualization specsEmit JavaScript, claim unseen evidence, or mutate the completed computation

Follow-ups retain state. Questions about an existing result stay with the analyst. A request that changes the backend, parameters, outputs, or computation returns to planning and validation.

Deployment

Pin physical GPUs by UUID

Each process sees its assigned physical GPU as device 0. This preserves existing CUDA code that calls cudaSetDevice(0) while preventing model inference from competing with graph jobs.

Evaluation before optimization

Keep correctness and domain coverage measurable

The checked-in query corpus covers every operation and all nine domains in separate future-training and held-out splits. Reports preserve the corpus hash, generation settings, per-domain scores, raw constrained output, errors, and latency. The current Qwen baseline passed all 13 held-out routes and all 13 held-out execution plans. The planning gate checks exact parameters, optional outputs, auxiliary-file roles, missing inputs, and backend allowlists through the production validator. These are regression gates for the curated set, not a claim of general language understanding. Backend/configuration optimization remains a later, separately evaluated selector based on graph features and hardware; it never weakens the deterministic plan validator.
