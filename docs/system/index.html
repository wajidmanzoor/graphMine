User journey

Domain first, then computation

01 · CONTEXT

Choose a domain

Fraud, bioinformatics, cybersecurity, social networks, e-commerce, knowledge graphs, infrastructure, mobility, or general analysis.

02 · INPUT

Upload research files

Canonical graph JSON and edge lists are normalized. Query graphs, motifs, updates, and partitions receive explicit roles.

03 · PLAN

Family → problem → algorithm

The planner maps the question to the current native catalog and builds a typed workflow. Explore all problem families and their algorithms.

04 · VALIDATE

Constrain execution

The orchestrator checks every backend, parameter, output flag, file ID, ownership boundary, and compiled capability.

05 · RUN

Execute the approved workflow

The scheduler runs native operations on compatible CPU or GPU implementations. Durable status, cancellation and revision checks keep execution tied to the selected inputs and plan.

06 · EXPLORE

Explain and inspect results

The analyst selects computed facts and introduces the answer. Fixed tables, charts and network views expose results, completeness and provenance.

Two LLM modes

One model, two narrow responsibilities

Mode Receives Produces Cannot do
Planner User question, domain, input metadata, task families and operation contracts A constrained intent and validated workflow plan Bypass execution validation or invent an unavailable operation
Analyst Saved workflow, computed facts, result scope and conversation context A lead sentence and selection of verified facts for the answer Invent computed values, emit executable visualization code, or mutate results

Follow-ups retain state. Questions about an existing result stay with the analyst. A request that changes the backend, parameters, outputs, or computation returns to planning and validation.

Evaluation before optimization

Keep correctness and domain coverage measurable

Native execution evidence, application regression checks and model evaluations have distinct scopes. The execution gate binds admitted profiles to matching implementations and evidence. Application checks cover planning contracts, ownership, workflow revisions and result handling. Model reports retain their original corpus and runtime scope; they do not automatically establish accuracy for newly added problems.
