# GraphMine Version 1

This is the historical 2026-10-01 release scope and its evaluation record.
For the current 37-problem, 18-operation catalog, see
[the algorithm expansion](ALGORITHM_EXPANSION.md). These v1 scores do not measure
the new tools or their routing.

GraphMine v1 is the correctness-first release of the private-LAN intelligent
GPU graph-mining system. It intentionally exposes only problem families with a
validated implementation. Unsupported formal problems remain visible in the
catalog and are rejected explicitly rather than routed to a nearby algorithm.

## Release scope

- Browser UI for domain selection, graph and auxiliary-file upload,
  conversation, streamed job state, result interpretation, and interactive
  visualizations.
- FastAPI service with token authentication, durable SQLite state, isolated
  file/job workspaces, a serial compute-GPU queue, WebSocket events, and
  authenticated operational counters.
- One local Qwen model with schema-constrained planner and analyst roles.
- A deterministic validation and execution boundary; the model cannot execute
  commands or bypass the GraphMine operation catalog.
- Thirteen operations representing twelve validated problem families.
- Runtime selection among compiled validated backends, including an optional
  benchmark-derived policy for `auto` requests.
- Reproducible native, API, browser-contract, model-evaluation, benchmark, and
  live end-to-end acceptance commands.

## Deliberate v1 boundary

The following formal problem definitions remain unsupported until a GPU
implementation passes the same correctness gate as the shipped portfolio:

- densest subgraph;
- densest k-subgraph;
- k-truss decomposition;
- graphlet counting;
- frequent subgraph mining;
- overlapping community detection;
- link prediction;
- graph anomaly detection.

Parallel Louvain, Parallel Leiden, and Parallel Leiden+ are validated catalog
entries but remain optional build targets because their Kokkos dependencies
are not part of the default build. gLeiden provides the compiled v1 community
detection path.

## Acceptance gates

Version 1 is releasable only when all of the following are true:

1. The release diff is fully accounted for and all generated catalogs and
   schemas are current.
2. Python/API tests, frontend checks, shell checks, and every enabled native
   backend test pass.
3. The capability probe reports 20 problem definitions, 13 operations, nine
   domain profiles, and at least one compiled backend for every operation.
4. The V1 routing, safety, and planning reports match the current evaluation
   corpus and meet the exact thresholds documented in `agent/README.md`.
5. The benchmark harness rejects incorrect runs and can produce a deterministic
   backend policy with a measured evaluation report.
6. A clean two-GPU deployment passes the live upload -> plan -> execute ->
   interpret -> visualize -> follow-up smoke test.
7. Restart, cancellation, authorization, session isolation, and bounded-result
   behavior are covered by automated tests.

## Verified V1.0.0 snapshot

The 2026-10-01 target-host release run passed:

- 117/117 Qwen routing cases, 20/20 unsupported/ambiguous safety cases, and
  117/117 complete planning cases across all nine domains;
- 69/69 correctness-gated benchmark records spanning 13 operations and all 23
  compiled backends;
- 18/18 enabled native tests, with the three optional Kokkos community tests
  explicitly disabled and the compiled gLeiden test passing;
- 37/37 Python/API/release-artifact tests and the real headless Firefox browser
  flow;
- the live upload -> Qwen plan -> RDMCE GPU execution -> Qwen interpretation ->
  visualization -> interpretation-only follow-up smoke test.

The exact model reports and benchmark evidence are linked from
`agent/README.md`. These are release-regression results on the curated V1
corpora and smoke graphs, not a general model-quality or performance claim.

## Operator sequence

1. Build and validate with `deploy/validate-v1.sh`.
2. Create the private runtime configuration with `deploy/configure-v1.sh`.
3. Start vLLM and the agent using the supplied systemd units or the two
   foreground launchers.
4. Run `graphmine-agent smoke-test` against the live API.
5. Open `http://GPU_SERVER_LAN_IP:8000` from the research computer.

Detailed installation, security, benchmark, and recovery procedures are kept
in `agent/README.md` and `deploy/README.md`.
