How the catalog is organized

Problem families → Problems → Algorithms

Begin with a family of related questions. Choose the precise problem, then compare its algorithms and CPU or GPU implementations. The catalog includes all formal contracts plus a separate group of graph-record query utilities.

01

Problem family

A related area of graph analysis: cliques, centrality, traversal, learning, flow, or another family in the catalog.

02

Formal problem

The exact question and contract. Maximum clique, maximal clique enumeration and k-clique counting are different problems in the same family.

03

Algorithm and implementation

Choose an operation and implementation, such as RDMCE for maximal cliques. Check its parameters, device support, guarantees and profile limits.

Quickstart

Compile once. Query repeatedly.

Start with the native CPU runtime below. The CUDA build adds GPU implementations through the same interface. See the native build guide for dependencies and GPU options. Queries use the compiled library.

Check your build: use graphmine-native catalog to inspect its families, problems, algorithms and compiled backends.

1 Configure and build 
cmake -S library/runtime -B build/native \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/native --parallel \
  --target graphmine_native_cli
2 Inspect this build 
build/native/graphmine-native catalog
3 Run an operation 
build/native/graphmine-native run \
  triangle-counting graph.json \
  --device cpu

Canonical graph input

One JSON graph format at every boundary.

All vertices—including isolated vertices—are declared explicitly. Edges reference stable external IDs. Backend adapters normalize only what the selected problem contract permits.

  • Integer or nonempty string vertex and edge IDs
  • Directedness, self-loop, and parallel-edge policy declared
  • Optional labels, types, weights, timestamps, and attributes
  • Strict validation before backend execution
Read the contract graphmine validate --graph graph.json

Predictable results

Outputs explain both the answer and how it was produced.

Always present

Required problem output

Counts, cliques, assignments, scores, or decompositions defined by the selected operation contract.

Flag controlled

Optional materialization

Instances, rankings, per-vertex counts, edge cuts, and other large fields appear only when explicitly requested.

Every execution

Provenance and diagnostics

Backend identity, input and implementation fingerprints, quality, completeness, timings and structured failures travel with the result.

Native C++ API

One native runtime for every family.

Discover families, problems and operation contracts through graphmine::runtime::request(). Send a run request with its canonical input, parameters and device policy, then inspect the structured result. C and Python bindings use the same native core.

01Discover the problem and operation contract
02Supply inputs, parameters and a device
03Inspect results, quality and provenance
catalog.cpp 
#include <graphmine/runtime.hpp>
#include <iostream>

int main() {
  // Families, formal problems and algorithm profiles.
  const auto catalog = graphmine::runtime::request(
      R"({"command":"catalog"})");
  std::cout << catalog << '\n';
}
