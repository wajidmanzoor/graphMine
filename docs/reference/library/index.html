Execution flow

Every supported operation follows the same boundary:

  1. graphmine::Graph validates and preserves the canonical external graph.
  2. A problem options object chooses a validated backend and optional outputs.
  3. The problem class supports() checks graph/profile compatibility.
  4. run() normalizes the graph and dispatches through an internal backend interface.
  5. A backend adapter invokes the preserved research implementation, checks and materializes requested results, restores external IDs, and returns an ExecutionResult<T> with provenance and timings.

The public problem classes are in library/include/graphmine/problems/. Backend boundaries and CUDA translation units are in library/src/backends/. Use each function page's definition link, "References", and "Referenced by" sections to follow a call path.

CUDA entries

Doxygen indexes .cu and .cuh as C++. CUDA qualifiers are removed only for declaration parsing; the linked source view always shows the exact __global__, __device__, __host__, launch configuration, synchronization, and memory-space declarations compiled by GraphMine.
