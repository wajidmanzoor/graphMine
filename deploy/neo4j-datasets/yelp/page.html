Data Loading

Overview

Data import is handled in two stages: node creation followed by sequential edge ingestion. We put all the csv files under the data import directory of Neo4j. This directory can be set in the neo4j.conf file using the parameter 'dbms.directories.import'.

For the implementation of Yelp Open Dataset on Neo4j, we used the original files downloaded from their website. We will read the JSON files unpacked from the downloaded file to complete node and edge imports.

Create Indices

To speed up the import process and future queries, we create B+-tree indices for some node labels.

cypher 
// For Users
CREATE INDEX user_user_id_index FOR (u:User) ON (u.user_id);
// For Businesses
CREATE INDEX business_id_index FOR (b:Business) ON (b.id);

Define Edges

Then we define the REVIEW and WROTE edges.

cypher 
CALL apoc.periodic.iterate(
  "CALL apoc.load.json('file:///yelp/yelp_academic_dataset_review.json') YIELD value",
  "
  MATCH (u:User {user_id: value.user_id})
  MATCH (b:Business {id: value.business_id})
  CREATE (r:Review {
    id: value.review_id,
    stars: value.stars,
    date: value.date,
    text: value.text,
    useful: value.useful,
    funny: value.funny,
    cool: value.cool
  })
  CREATE (u)-[:WROTE]->(r)
  CREATE (r)-[:REVIEWS]->(b)
  ",
  {batchSize: 1000, parallel: false}
)

Then we define the TIP and FOR edges. We would also create Tip nodes during the process.

cypher 
CALL apoc.periodic.iterate(
  "CALL apoc.load.json('file:///yelp/yelp_academic_dataset_tip.json') YIELD value",
  "
  MATCH (u:User {user_id: value.user_id})
  MATCH (b:Business {id: value.business_id})
  CREATE (t:Tip {
    text: value.text,
    date: value.date,
    compliment_count: value.compliment_count
  })
  CREATE (u)-[:TIPPED]->(t)
  CREATE (t)-[:FOR]->(b)
  ",
  {batchSize: 1000, parallel: false}
)

Then we define the IN_CATEGORY edges. We would create Category nodes during the process.

cypher 
CALL apoc.periodic.iterate(
  "MATCH (b:Business) WHERE b.categories IS NOT NULL RETURN b",
  "
  WITH b, apoc.text.split(b.categories, ',') AS categoryList
  UNWIND categoryList AS rawCategory
  WITH b, trim(rawCategory) AS category
  MERGE (c:Category {name: category})
  CREATE (b)-[:IN_CATEGORY]->(c)
  ",
  {batchSize: 1000, parallel: false})

Then we define the FRIEND edges.

cypher 
CALL apoc.periodic.iterate(
  "MATCH (u:User) WHERE u.friends IS NOT NULL RETURN u",
  "
  WITH u, apoc.text.split(u.friends, ', ') AS friendIds
  UNWIND friendIds AS friendId
  MATCH (f:User {user_id: friendId})
  CREATE(u)-[:FRIEND]->(f)
  ",
  {batchSize: 10000, parallel: false})

Q1. Find the friends of all "John"s

Subcategory: T1.1 One-Hop Neighbors

This query retrieves the name and user ID of up to 20 friends of users named "John".

cypher 
MATCH (:User {name: "John"})-[:FRIEND]->(friend)
RETURN friend.name, friend.user_id
LIMIT 20

Equivalent query in GQL standard:

gql 
MATCH (:User {name: "John"})-[:FRIEND]->(friend)
RETURN friend.name, friend.user_id
LIMIT 20

Q2. Find all users within two friend hops of a given user

Subcategory: T1.2 k-Hop Neighborhood

This query finds all distinct users reachable within one or two FRIEND hops from a starting user.

cypher 
MATCH (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND*1..2]-(neighbor:User)
WHERE neighbor <> start
RETURN DISTINCT neighbor.name AS name, neighbor.user_id AS user_id
ORDER BY name, user_id
LIMIT 100

Equivalent query in GQL standard:

gql 
MATCH p = (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{1,2}(neighbor:User)
WHERE neighbor != start
RETURN DISTINCT neighbor.name AS name, neighbor.user_id AS user_id
ORDER BY name, user_id
LIMIT 100

Q3. Get 3-hop neighbors of a given user

Subcategory: T1.3 Exact kth-Hop Neighbors

This query identifies the unique names and user IDs of all neighbors exactly three friend-connections away from a given user.

cypher 
MATCH (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND*3]-(neighbor)
WHERE neighbor.user_id <> "Oi1qbcz2m2SnwUeztGYcnQ"
RETURN DISTINCT neighbor.name, neighbor.user_id

Equivalent query in GQL standard:

gql 
MATCH (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{3}(neighbor)
WHERE neighbor.user_id != "Oi1qbcz2m2SnwUeztGYcnQ"
RETURN DISTINCT neighbor.name, neighbor.user_id

Q4. Find high-review-count users within two friend hops

Subcategory: T1.4 Neighborhood with Property Filter

This query finds distinct users within one or two FRIEND hops of a starting user, filtered to users with at least 100 reviews and an average rating of 4.0 or higher.

cypher 
MATCH (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND*1..2]-(neighbor:User)
WHERE neighbor <> start
  AND neighbor.review_count >= 100
  AND neighbor.average_stars >= 4.0
RETURN DISTINCT neighbor.name AS name,
       neighbor.user_id AS user_id,
       neighbor.review_count AS review_count,
       neighbor.average_stars AS average_stars
ORDER BY review_count DESC, average_stars DESC
LIMIT 100

Equivalent query in GQL standard:

gql 
MATCH p = (start:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{1,2}(neighbor:User)
WHERE neighbor != start
  AND neighbor.review_count >= 100
  AND neighbor.average_stars >= 4.0
RETURN DISTINCT neighbor.name AS name,
       neighbor.user_id AS user_id,
       neighbor.review_count AS review_count,
       neighbor.average_stars AS average_stars
ORDER BY review_count DESC, average_stars DESC
LIMIT 100

Q7. Check whether Steven can reach Niki within four friend hops

Subcategory: T2.3 Reachability between Two Nodes

This query tests whether a bounded friend path exists between two User nodes.

cypher 
MATCH (source:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"}),
      (target:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
RETURN EXISTS {
  MATCH (source)-[:FRIEND*1..4]-(target)
} AS reachable

Equivalent query in GQL standard:

gql 
MATCH p = ANY (source:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{1,4}(target:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
RETURN true AS reachable

Q8. Find the shortest friend path between Steven and Niki

Subcategory: T2.4 Shortest Path

This query returns the shortest bounded path connecting two users in the friend graph.

cypher 
MATCH p = shortestPath(
  (:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND*1..6]-(:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
)
RETURN [n IN nodes(p) | n.name] AS user_path, length(p) AS hop_count

Equivalent query in GQL standard:

gql 
MATCH p = SHORTEST (:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{1,6}(:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
RETURN p

Q9. Enumerate simple friend paths between Steven and Niki up to length three

Subcategory: T2.5 All Simple Paths up to Length k

This query materializes acyclic friend paths up to three hops between two users.

cypher 
MATCH p = (:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND*1..3]-(:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
WHERE all(i IN range(0, size(nodes(p)) - 1)
          WHERE single(n IN nodes(p) WHERE n = nodes(p)[i]))
RETURN [n IN nodes(p) | n.user_id] AS user_ids, length(p) AS hop_count
ORDER BY hop_count ASC
LIMIT 20

Equivalent query in GQL standard:

gql 
MATCH p = ACYCLIC (:User {user_id: "Oi1qbcz2m2SnwUeztGYcnQ"})-[:FRIEND]-{1,3}(:User {user_id: "WwulXySQN8t2hwqH_yWurA"})
RETURN p
LIMIT 20

Q11. Find friend squares around Steven

Subcategory: T3.2 Square Detection

This query searches for four-user cycles that include Steven.

cypher

Q22. Find the total number of reviews and tips for each business

Subcategory: T4.7 Union and Intersection

This query calculates the combined count of reviews and tips for every business, sorting them in descending order of total user interactions.

cypher 
MATCH (b:Business)
OPTIONAL MATCH (b)<-[:REVIEWS]-(r:Review)
WITH b, count(DISTINCT r) AS num_reviews
OPTIONAL MATCH (b)<-[:FOR]-(t:Tip)<-[:TIPPED]-(:User)
WITH b, num_reviews, count(DISTINCT t) AS num_tips
RETURN b.name AS business_name,
       num_reviews,
       num_tips,
       num_reviews + num_tips AS total
ORDER BY total DESC

Equivalent query in GQL standard:

gql 
MATCH (b:Business)
OPTIONAL MATCH (b)<-[:REVIEWS]-(r:Review)
OPTIONAL MATCH (b)<-[:TIPPED]-(t:Tip)
RETURN b.name AS business_name,
       count(DISTINCT r) AS num_reviews,
       count(DISTINCT t) AS num_tips,
       (count(DISTINCT r) + count(DISTINCT t)) AS total
ORDER BY total DESC

This query finds businesses that have received both reviews and tips, returning the counts of each along with their combined total.

cypher 
MATCH (b:Business)<-[:REVIEWS]-(r:Review)
WITH b, count(DISTINCT r) AS num_reviews
MATCH (b)<-[:FOR]-(t:Tip)<-[:TIPPED]-(:User)
WITH b, num_reviews, count(DISTINCT t) AS num_tips
RETURN b.name AS business_name,
