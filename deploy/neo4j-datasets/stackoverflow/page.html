Schema Diagram and Graph Statistics

An Interesting Discovery

When we import data to Neo4j, we discovered that there are some edge count discrepancies with other database platforms. Notably, the number of ACCEPTS edges on Neo4j is 11,755,050, which on other platforms are 11,755,280. The number of CREATED_BY edges on Neo4j is 71,196, but 109,349 on other platforms. The number of LAST_EDITED_BY edges on Neo4j is 22,832,774, but 22,880,943 on other platforms. All three discrepancies share the same underlying cause: Neo4j's MATCH clause requires both the source and destination nodes to already exist before an edge can be created. When either node is absent due to deleted users, deleted posts, or records filtered out during CSV cleaning Neo4j silently skips that edge. The other three engines are more permissive and either auto-create missing nodes or build edges independently of strict node existence checks.

Our solution is to keep Neo4j at its naturally loaded counts and document these as known discrepancies. Creating stub nodes to artificially match the other engines would inflate node counts and introduce property-less nodes that skew benchmarking results. The total difference of 86,552 edges out of 782,719,894 represents a 0.011% variance, which is negligible for benchmarking purposes. This is a meaningful finding; it highlights a fundamental behavioral difference in how graph databases handle incomplete datasets during bulk loading, with Neo4j enforcing strict referential integrity while the other engines are more permissive.

Create User Nodes (785s)

First we will start with User nodes. The original users.csv file downloaded have some syntax problems that cause Neo4j to fail on loading. So we first used a python script to clean the data and save it as users_clean.csv. You can find this Python script file named clean_users_csv.py in the Download tab.

Then, run the following command to use the cleaner script.

bash 
python clean_users_csv.py users.csv users_clean.csv --strip-backslashes

Now you can run the following cypher query to import User nodes.

cypher 
CALL apoc.periodic.iterate(
    "LOAD CSV WITH HEADERS FROM 'file:///stackoverflow/users_clean.csv' AS row RETURN row",
    "
    MERGE (u:User {user_id: toInteger(row.id)})
    SET u.display_name      = row.display_name,
        u.about_me          = row.about_me,
        u.age               = toInteger(row.age),
        u.creation_date     = row.creation_date,
        u.last_access_date  = row.last_access_date,
        u.location          = row.location,
        u.reputation        = toInteger(row.reputation),
        u.up_votes          = toInteger(row.up_votes),
        u.down_votes        = toInteger(row.down_votes),
        u.views             = toInteger(row.views),
        u.profile_image_url = row.profile_image_url,
        u.website_url       = row.website_url
    ",
    {batchSize: 20000, parallel: false, retries: 2}
);

VOTE_ON Edges (20921.2s)

Next, we will create the VOTE_ON edges from Votes to Post_question and Post_answer.

cypher 
CALL apoc.periodic.iterate(
    "
    MATCH (v:Vote)
    WHERE v.post_id IS NOT NULL
      AND v.post_id <> 0
    RETURN
        v.vote_id AS vote_id,
        v.post_id AS post_id
    ",
    "
    MATCH (v:Vote {vote_id: vote_id})

    OPTIONAL MATCH (pq:Post_question {post_id: post_id})
    OPTIONAL MATCH (pa:Post_answer {post_id: post_id})

    FOREACH (_ IN CASE WHEN pq IS NULL THEN [] ELSE [1] END |
        MERGE (v)-[:VOTE_ON]->(pq)
    )

    FOREACH (_ IN CASE WHEN pa IS NULL THEN [] ELSE [1] END |

LINK_TO Edges (462.8s)

Next, we will create the LINK_TO edges from Post_question to Post_question.

cypher 
CALL apoc.periodic.iterate(
    "
    LOAD CSV WITH HEADERS
    FROM 'file:///stackoverflow/posts_links.csv' AS row

    WITH
        toIntegerOrNull(row.id) AS post_link_id,
        toIntegerOrNull(row.post_id) AS source_post_id,
        toIntegerOrNull(row.related_post_id) AS target_post_id,
        toIntegerOrNull(row.link_type_id) AS link_type_id,
        row.creation_date AS creation_date

    WHERE post_link_id IS NOT NULL
      AND source_post_id IS NOT NULL
      AND target_post_id IS NOT NULL
      AND source_post_id <> 0
      AND target_post_id <> 0

    RETURN post_link_id, source_post_id, target_post_id,
           link_type_id, creation_date
    ",
    "
    MATCH (pq1:Post_question {post_id: source_post_id})
    MATCH (pq2:Post_question {post_id: target_post_id})

    MERGE (pq1)-[r:LINK_TO {post_link_id: post_link_id}]->(pq2)
    SET r.link_type_id = link_type_id,
        r.creation_date = creation_date
    ",
    {
        batchSize: 20000,
        parallel: false,
        retries: 2
    }
);

Q27. Vote Distribution

Subcategory: T3.3 Star Pattern Query; T4.7 Union and Intersection

This query ranks users by the total number of votes received across their questions and answers, combining both incoming vote relationships into one activity score.

cypher 
MATCH (u:User)
OPTIONAL MATCH (q:Post_question)-[:OWNED_BY]->(u)
OPTIONAL MATCH (vq:Vote)-[:VOTE_ON]->(q)
WITH u, COUNT(vq) AS q_votes
OPTIONAL MATCH (a:Post_answer)-[:ANSWERS_BY]->(u)
OPTIONAL MATCH (va:Vote)-[:VOTE_ON]->(a)
WITH u, q_votes, COUNT(va) AS a_votes
WITH u.user_id AS user_id,
     u.display_name AS display_name,
     q_votes + a_votes AS total_votes
WHERE total_votes > 0
RETURN user_id, display_name, total_votes
ORDER BY total_votes DESC;

Q29. User Pairs with Most Question-Answer Interactions

Subcategory: T3.5 Two-hop Join Pattern; T4.3 Ungrouped Edge Count and Property Statistics

This query finds answerer-questioner pairs connected through answer posts and question posts, counts how many times one user answered another user's questions, and returns pairs with at least five such interactions.

cypher 
MATCH (a:Post_answer)-[:ANSWERS_TO]->(q:Post_question)
MATCH (a)-[:ANSWERS_BY]->(answerer:User)
MATCH (q)-[:OWNED_BY]->(questioner:User)
WHERE answerer.user_id <> questioner.user_id
WITH (answerer.user_id + ':' + questioner.user_id) AS pair_key,
    COUNT(*) AS interaction_count
WHERE interaction_count >= 5
RETURN pair_key, interaction_count
ORDER BY interaction_count DESC

Q31. Users Who Earn Badges Fastest After Account Creation

Subcategory: Other

This query groups badge-earning events by user, estimates how many days elapsed between each user's account creation and first badge date, and returns the fastest badge earners.

cypher 
MATCH (u:User)-[:EARNED]->(b:Badge)
WHERE u.creation_date IS NOT NULL
    AND b.date IS NOT NULL
    AND u.creation_date <> ''
    AND b.date <> ''
WITH u.user_id AS user_id,
     u.display_name  AS display_name,
     u.creation_date AS creation_date,
     MIN(
        (toInteger(substring(b.date, 0, 4)) - toInteger(substring(u.creation_date, 0, 4))) * 365 +
        (toInteger(substring(b.date, 5, 2)) - toInteger(substring(u.creation_date, 5, 2))) * 30  +
        (toInteger(substring(b.date, 8, 2)) - toInteger(substring(u.creation_date, 8, 2)))
     ) AS min_days
WHERE min_days >= 0
RETURN user_id, display_name, min_days
ORDER BY min_days ASC, user_id ASC
LIMIT 100;

Q32. Percentage of Questions Answered Over the Years

Q33. Top 10 "Easiest" Gold Badges to Earn

Subcategory: Other

This query focuses on gold badges, counts distinct earners for each badge, estimates the fastest time from account creation to earning that badge, and returns the most commonly earned gold badges.

cypher

AND u.creation_date IS NOT NULL
AND b.date IS NOT NULL
AND u.creation_date <> ''

WITH b.name AS badge_name,
     COUNT(DISTINCT u.user_id) AS total_earners,

        (toInteger(substring(b.date, 0, 4)) - toInteger(substring(u.creation_date, 0, 4))) * 365 +
        (toInteger(substring(b.date, 5, 2)) - toInteger(substring(u.creation_date, 5, 2))) * 30  +
        (toInteger(substring(b.date, 8, 2)) - toInteger(substring(u.creation_date, 8, 2)))
     ) AS min_days
WHERE min_days >= 0
RETURN badge_name, total_earners, min_days
ORDER BY total_earners DESC
LIMIT 100;
